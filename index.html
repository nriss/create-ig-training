Training : créer un IG FHIR

Session d'1 heure : construire un implementation guide de A à Z avec quelques artifacts FHIR (profil, extension, jeu de valeurs, exemple).

Objectifs

  • Comprendre la structure d'un IG et le rôle de SUSHI et de l'IG Publisher.
  • Écrire en FSH un petit jeu d'artifacts FHIR.
  • Générer l'IG en local et le publier sur GitHub Pages.

Prérequis

Un compte GitHub. Tout le reste se fait sur GitHub.

1/ Qu'est-ce qu'un guide d'implémentation ?

Un guide d'implémentation (IG) explique comment utiliser FHIR pour un besoin précis. Il contient deux choses :

Des ressources techniques

Profils, extensions, jeux de valeurs, exemples… Ils permettent de valider automatiquement la conformité des ressources échangées.

Une partie narrative

Des pages qui expliquent comment utiliser les profils définis : contexte, cas d'usage, règles de mise en œuvre.

Pourquoi c'est important ?

FHIR est très générique de base : pour gagner en interopérabilité, il doit être contraint et spécifié. Par exemple, FHIR France a ajouté les contraintes françaises dans le guide FR Core, qui hérite lui-même du guide européen HL7 Europe Base and Core.

Autre exemple : le projet Annuaire Santé (les professionnels de santé français publiés sur une API FHIR) a son propre guide d'implémentation, Annuaire Santé, qui explique précisément comment fonctionne l'API et quelles ressources et quels paramètres de recherche sont supportés.

Qu'est-ce que FSH ?

FHIR Shorthand (FSH) est un langage textuel qui permet d'écrire les ressources techniques d'un IG de façon concise, plutôt que d'éditer à la main de longs fichiers JSON ou XML. L'outil SUSHI compile ensuite le FSH en ressources FHIR. 

Profile: TrainingPatient
Parent: Patient
* birthDate 1..1
