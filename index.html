Training : créer un IG FHIR

Session d'1 heure : construire un implementation guide de A à Z avec quelques artifacts FHIR (profil, extension, jeu de valeurs, exemple).

Objectifs

  • Comprendre la structure d'un IG et le rôle de SUSHI et de l'IG Publisher.
  • Écrire en FSH un petit jeu d'artifacts FHIR.
  • Générer l'IG en local et le publier sur GitHub Pages.

Déroulé (60 min)

  1. 0 – 10 min

    Panorama d'un IG

    FHIR, IG, FSH, SUSHI, IG Publisher : qui fait quoi. Structure d'un projet à partir de ansforge/IG-modele.

  2. 10 – 20 min

    Mise en place

    Cloner le modèle, renseigner sushi-config.yaml (identité, dépendances, pages, menu) et ig.ini.

  3. 20 – 40 min

    Écrire les artifacts en FSH

    Un Profile (contraintes sur une ressource), une Extension, un ValueSet avec son CodeSystem, et une Instance d'exemple.

  4. 40 – 50 min

    Pages et génération

    Rédiger une page Markdown (à partir du niveau ###), lancer sushi ., puis _genonce et lire le QA.

  5. 50 – 60 min

    Publication et questions

    Publier sur GitHub Pages, bonnes pratiques, pistes pour aller plus loin.

Prérequis

  • Git, Node.js (pour SUSHI), Java (pour l'IG Publisher).
  • Un éditeur de texte, idéalement avec l'extension FSH.
npm install -g fsh-sushi
git clone https://github.com/ansforge/IG-modele
cd IG-modele
sushi .

Exemple fil rouge en FSH

Profile: TrainingPatient
Parent: Patient
Title: "Patient (training)"
* identifier 1..*
* birthDate 1..1
* extension contains TrainingNationality named nationality 0..1

Extension: TrainingNationality
Title: "Nationalité"
* value[x] only CodeableConcept
* valueCodeableConcept from TrainingCountryVS (extensible)

ValueSet: TrainingCountryVS
Title: "Pays (training)"
* include codes from system TrainingCountryCS

CodeSystem: TrainingCountryCS
Title: "Pays (training)"
* #FR "France"
* #BE "Belgique"

Instance: TrainingPatientExample
InstanceOf: TrainingPatient
Usage: #example
* identifier.value = "123"
* birthDate = "1980-01-01"
