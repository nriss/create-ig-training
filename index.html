Training: create a FHIR IG

1-hour session: build an implementation guide from scratch with a few FHIR artifacts (profile, code system, value set, example).

Date: Thursday 19 November
Time: 11:00 – 12:30
Room: Malagueta 70

Objectives

  • Understand the role and structure of an implementation guide, of SUSHI and of the IG Publisher.
  • Generate the IG with the HL7 autobuild tool.
  • Write a small set of FHIR artifacts in FSH.

Prerequisites

A GitHub account. Everything else is done on GitHub.

Part 1: Introduction and context

What is an implementation guide?

An implementation guide (IG) explains how to use FHIR for a specific need. It contains two things:

Technical resources

Profiles, extensions, value sets, examples… They make it possible to automatically validate the conformance of the exchanged resources.

A narrative part

Pages explaining how to use the defined profiles: context, use cases, implementation rules.

Why is it important?

FHIR is very generic by default: to gain interoperability, it must be constrained and specified.

  • For example, HL7 France added the French constraints in the FR Core guide, which itself inherits from the European guide HL7 Europe Base and Core.
  • Another example: the Annuaire Santé project (French healthcare professionals published on a FHIR API) has its own implementation guide, Annuaire Santé, which explains precisely how the API works and which resources and search parameters are supported.

What is FSH?

FHIR Shorthand (FSH) is a text language used to write the technical resources of an IG concisely, instead of manually editing long JSON or XML files. The SUSHI tool then compiles the FSH into FHIR resources. 

Profile: TrainingPatient
Parent: Patient
* birthDate 1..1

Part 2: Creating and initializing the implementation guide

We are going to create your first implementation guide. It will define FHIR profiles that inherit from the European profiles and are conformant to them.

Step 1: configure the id and the canonical

Once your fork is created, open the sushi-config.yaml file and set these two values:

  • id: the identifier of your implementation guide once published, in the form org.fhir.[realm].[code].
  • canonical: the publication address of the IG. Make up an address.

The realm is the geographical or jurisdictional scope of the IG, following the HL7 naming convention: uv (universal), eu (Europe), fr (France), us (United States), etc. Replace [realm:uv|fr|...] with the value that suits you, for example eu for an IG intended to be used in Europe.

The only important point: the canonical address must end with /[code], where [code] is the last part of the id.

id: org.fhir.eu.monig
canonical: https://example.org/ig/monig

Also edit the ig.ini file: the ig line must point to the IG file generated from your id. 

ig = fsh-generated/resources/ImplementationGuide-org.fhir.eu.monig.json

Part 3: Configuring the auto-builder

The HL7 auto-builder automatically generates your IG on every commit.

  1. Check that your fork is a public repository.
  2. Install the FHIR IG Builder GitHub app on your account or on your repository.
  3. Make a commit: the generation is triggered and takes 2 to 3 minutes.

Your IG is then available at https://build.fhir.org/ig/<account>/<repository>/branches/<branch>. In case of error, the generation logs are published in the same place: find your repository in the list at build.fhir.org/ig/ to see the errors. Branch names may only contain letters, digits, _ and - (no /).

Note: it is also possible to generate the IG locally with the IG Publisher, but we will not cover it in this session, because it requires installing too many dependencies: Java, Node.js and SUSHI, Ruby and Jekyll, as well as Git.

Part 4: Adding FHIR artifacts

We will now enrich your implementation guide with FHIR artifacts written in FSH in the input/fsh folder: a profile that inherits from the European profiles, and the resources associated with it.

Step 1: add the dependency on HL7 Europe Base and Core

To be able to inherit from the European profiles, first add the dependency on the HL7 Europe Base and Core guide in sushi-config.yaml (documentation): 

dependencies:
  hl7.fhir.eu.base: 2.0.1

Step 2: create the resources

You are going to create 4 resources:

  1. An Observation profile to indicate eye color.
  2. A CodeSystem containing colors.
  3. A ValueSet containing colors.
  4. An example instance of this profile.

The FSH reference contains examples to help you.

Part 5: Publishing an official version

The "build" version generated by the autobuild is a continuous integration version. To publish an official version, you need to use the -go-publish option of the IG Publisher, which is not covered in this training. See the IG Publisher documentation.

Partie 1 : Introduction et contexte

Qu'est-ce qu'un guide d'implémentation ?

Un guide d'implémentation (IG) explique comment utiliser FHIR pour un besoin précis. Il contient deux choses :

Des ressources techniques

Profils, extensions, jeux de valeurs, exemples… Ils permettent de valider automatiquement la conformité des ressources échangées.

Une partie narrative

Des pages qui expliquent comment utiliser les profils définis : contexte, cas d'usage, règles de mise en œuvre.

FHIR est très générique de base : pour gagner en interopérabilité, il doit être contraint et spécifié.

  • Par exemple, HL7 France a ajouté les contraintes françaises dans le guide FR Core, qui hérite lui-même du guide européen HL7 Europe Base and Core.
  • Autre exemple : le projet Annuaire Santé (les professionnels de santé français publiés sur une API FHIR) a son propre guide d'implémentation, Annuaire Santé, qui explique précisément comment fonctionne l'API et quelles ressources et quels paramètres de recherche sont supportés.

Qu'est-ce que FSH ?

Profile: TrainingPatient
Parent: Patient
* birthDate 1..1

Partie 2 : Création et initialisation du guide d'implémentation

Nous allons créer votre premier guide d'implémentation. Il définira des profils FHIR qui hériteront des profils européens et seront conformes à ceux-ci.

Étape 1 : configurer l'id et le canonical

Une fois votre fork créé, ouvrez le fichier sushi-config.yaml et renseignez ces deux valeurs :

  • id : l'identifiant de votre guide d'implémentation une fois publié, de la forme org.fhir.[realm].[code].
  • canonical : l'adresse de publication de l'IG. Inventez une adresse.

Le realm est le périmètre géographique ou juridictionnel de l'IG, dans la convention de nommage d'HL7 : uv (universel), eu (Europe), fr (France), us (États-Unis), etc. Remplacez [realm:uv|fr|...] par la valeur qui vous convient, par exemple eu pour un IG destiné à être utilisé en Europe.

Le seul point important : l'adresse du canonical doit se terminer par /[code], où [code] est la dernière partie de l'id.

id: org.fhir.eu.monig
canonical: https://example.org/ig/monig

Modifiez aussi le fichier ig.ini : la ligne ig doit pointer vers le fichier de l'IG généré à partir de votre id. 

ig = fsh-generated/resources/ImplementationGuide-org.fhir.eu.monig.json

Partie 3 : Configurer l'auto-builder

L'auto-builder d'HL7 génère automatiquement votre IG à chaque commit.

  1. Vérifiez que votre fork est un dépôt public.
  2. Installez l'application GitHub FHIR IG Builder sur votre compte ou sur votre dépôt.
  3. Faites un commit : la génération se déclenche, et dure 2 à 3 minutes.

Votre IG est ensuite disponible à l'adresse https://build.fhir.org/ig/<compte>/<dépôt>/branches/<branche>. En cas d'erreur, les logs de génération sont publiés au même endroit : retrouvez votre dépôt dans la liste build.fhir.org/ig/ pour consulter les erreurs. Les noms de branches ne doivent contenir que des lettres, des chiffres, _ et - (pas de /).

Note : il est aussi possible de générer l'IG en local avec l'IG Publisher, mais nous ne le verrons pas dans cette session, car cela demande d'installer trop de dépendances : Java, Node.js et SUSHI, Ruby et Jekyll, ainsi que Git.

Partie 4 : Ajout d'artifacts FHIR

Nous allons maintenant enrichir votre guide d'implémentation avec des artifacts FHIR écrits en FSH dans le dossier input/fsh : un profil qui hérite des profils européens, ainsi que les ressources qui lui sont associées.

Étape 1 : ajouter la dépendance vers HL7 Europe Base and Core

Pour pouvoir hériter des profils européens, ajoutez d'abord la dépendance vers le guide HL7 Europe Base and Core dans sushi-config.yaml (documentation) : 

dependencies:
  hl7.fhir.eu.base: 2.0.1

Étape 2 : créer les ressources

Vous allez créer 4 ressources :

  1. Un profil d'Observation pour indiquer la couleur des yeux.
  2. Un CodeSystem contenant des couleurs.
  3. Un ValueSet contenant des couleurs.
  4. Une instance d'exemple de ce profil.

La référence FSH contient des exemples pour vous aider.

Partie 5 : Publication d'une version officielle

La version « build » générée par l'autobuild est une version en intégration continue. Pour publier une version officielle, il faut utiliser l'option -go-publish de l'IG Publisher, qui n'est pas vue dans cette formation. Voir la documentation de l'IG Publisher.
